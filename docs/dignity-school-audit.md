# Dignity audit across schools

This audit traces the dignity predicates in the principal natal, event, and rectification paths. It does **not** certify every interpretation in the much larger historical rule catalogue. Source-specific conditions, event eligibility, and whether a finding participates in a score remain separate decisions. A computational match is not evidence that a prediction is true.

## The shared fact and the legacy label

`dignityOf` is a historical, **whole-sign**, single display label. It prioritizes exaltation, debilitation, moolatrikona sign, own sign, then friendship. That priority loses overlapping facts. For example, Mercury in Virgo is in both an exaltation sign and a sign it owns; at 15–20° it is also in the particular BPHS moolatrikona range. Moon in Taurus has a corresponding exaltation-sign/moolatrikona overlap. The degree-specific context in `planet-dignity.ts` carries these facts independently, using [BPHS chapter 3, verses 49–54](https://vedicpupil.in/library/books/brihat-parashara-hora-shastra/chapter-3). Owning an entire sign is distinct from the narrower degree portion the text calls swakshetra. A label alone is not a full strength judgment.

| School or module | Audited behavior and disposition |
| --- | --- |
| Parashari natal houses and padas | Own-sign predicates now use sign ownership, rather than requiring the single label to say `Own sign` or `Moolatrikona`. This restores own-sign checks for Mercury in Virgo. BPHS 47.81–82's Venus moolatrikona rule already uses the explicit 0–15° range. Combined own/exalt/friendly checks retain their sign-level semantics. |
| Sarvartha Chintamani | 9.9's Saturn-own check now includes Saturn's Aquarius sign even when the legacy label says moolatrikona. House rules 3.17 and 10.22 similarly retain the own-sign case. The old automatic 9.3, 9.4, 9.20 and 9.22 tests omitted or misstated required conditions; they remain listed but are **not automatically assessed**. 9.21 now also requires the lagna lord's aspect under the existing quarter-aspect convention. See [Sarvartha chapter 9](https://vedicpupil.in/library/books/sarvartha-chintamani/chapter-9). Whether 9.22's moolatrikona is degree-limited and which aspect standard to apply need source-specific work before enabling it. |
| BNN | Existing Sun and Mars "dignified" predicates now include their own signs when the single display label says moolatrikona. Their specific predictive wording lacks a verified page-level source and is explicitly provisional. BNN's own `effectiveDignity` may change an exaltation/debilitation label according to its separate cancellation conventions; it is not silently imported into other schools. Mercury in Virgo when the exaltation condition is set aside but ownership still applies needs a sourced BNN-specific decision. |
| Jaimini | Rasi and D9 dignity uses the existing sign-level `dignityOf`; this does not establish a BPHS degree-specific moolatrikona portion in a divisional chart. The karaka text now identifies moolatrikona **signs** and treats a strong D9 as a possible mitigating clue, not a guaranteed repair. Rasi aspects and other stated school conditions remain separate. |
| KP | The registered KP event and natal subset uses cusp and stellar signification; the audit found no generic planetary-dignity point in that subset. Adding one solely because another school uses it would change the method without a KP source. |
| ALP | The qualified marriage score uses the progressed pada-navamsa relationship, not a generic dignity point. Other ALP interpretations remain their own declarative rules. The one-second scan calls the same relationship predicate and event-point calculation as the ordinary ALP reading. |
| Prasna Marga | For 14.39–41, [Raman's note on 14.40](https://storage.yandexcloud.net/j108/library/touvip7g/Panangadu_Nambudhiri_-_Prasna_Marga_%28Part_I%29.pdf) names own, exaltation and friendly placements as strong, and debilitation as weak. Neutral and inimical signs now remain unresolved, rather than automatically becoming strong. The check no longer substitutes BNN's `effectiveDignity`; mixed or unnamed house placements also remain unresolved. The app's house-to-karaka mapping and whole-sign interpretation are provisional. The older 8.6 question-chart strength proxy is a separate unresolved convention and is not claimed to follow 14.40. |
| Vargas and nodes | BPHS varga designations explicitly use signs; they are not automatically given D1's degree bands. Ordinary shared node dignity is undefined. BPHS 47.34–35's separate node convention remains scoped to those period rules; it is not a universal Rahu/Ketu exaltation or ownership fact. |

Regression tests exercise overlapping Mercury facts, degree boundaries, the affected BNN predicates, the Sarvartha conditions, and the Prasna tri-state. They establish implementation consistency, not whether any traditional interpretation is accurate. Future rules must specify whether they need a sign, a degree range, a divisional fact, a school-specific adjustment, or a combination; an event scorer must explicitly register a rule before it can affect an event total.
