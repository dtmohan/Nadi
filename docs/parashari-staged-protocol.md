# Staged period-lord experiment: exploratory protocol

This follow-up was specified after the earlier third-period results were seen. Both public cohorts are reused, so the analysis is exploratory even though this protocol is written before its results are calculated. No user's private chart is included. It tests a staged operationalization inspired by Paul Manley, *Birth Time Rectification* (2022), chapter 4, "The 345 Method"; it is not a reproduction or validation of the full book method.

## Rule under test

For each event and candidate birth time, a period lord has a **primary divisional link** if Nadi's existing partial check finds a connection to the relevant event house, its lord, or the event significator in the event's division. This check is incomplete: a missing link means **unresolved in this implementation**, not that the event is impossible. It does not account for all six of Manley's factors, indirect node links, yogas, or qualitative judgment. The app's sign-aspect and significator conventions apply. D1 clues may be inspected separately but are not an additional Boolean prerequisite here; the source does not specify this app-defined hard threshold.

For every event, the first-stage condition is that **both** the main and subperiod have a primary divisional link. Its third-period condition is met only if that event's first-stage condition is met and the third lord also has a primary divisional link. At the case level, stage 2 retains every candidate with the maximum number of first-stage-supported input events. Stage 3 then retains every tied stage-2 candidate with the maximum number of their first-stage-supported input events also supported by the third lord. A later event or period cannot compensate for an earlier period in the **same event**, and the third-period count cannot promote a candidate over one with more stage-2 events. If no candidate has any first-stage-supported event, retain the entire window and mark it unresolved. These are deliberately strict research conventions, not the author's published numeric algorithm, probabilities, or automatic disproof of other candidates.

For comparison, compute the prior research-only additive M2 and M3 counts on the *same new scan rows*. This makes sampling resolution and events identical for this follow-up, but does not make either rule equivalent to Nadi's v2/v3. Record all ties, coverage, and the ±5-minute and ±10-minute reported-time touches; do not pick a candidate because it is near the reference. Reporting more supported events within the partial check is not a calibrated confidence measure.

## Inputs and uncertainty

Use `parashari-third-period-fresh-cases.json` and `parashari-divisional-v3-cases.json` from the prior research. Keep the former labeled **previously evaluated seven**, not fresh. Original birth records were not inspected and reported times may be rounded, misremembered, use the wrong historical time standard or be outside a ±30-minute scan. They are uncertain, independent reference information and not absolute minute-level ground truth. Retain the earlier primary LMT convention for Fitzgerald; a historical civil-time sensitivity was documented in the earlier report.

For each subject, sort distinct event dates and alternate them into input and held-out sets, beginning with input. Scan ±30 minutes from the reported time on a five-second grid, refining detected changes to 200 ms. The scan may miss changes that reverse within one sample. Date-only event clocks use local noon for this main comparison, but this is an assumption, not a known time. At the reported birth time, compare 00:01, noon and 23:59 for each date-only event and count changes in staged support; these samples do not exhaust all possible times. Held-out controls at the reported birth time are the same event shifted by ±60, ±120 and ±180 days. Report counts of first-stage and third-stage support for actual and comparison dates; controls are correlated, age/order-unmatched and not known non-events.

## Fourth and fifth levels

Calculate fourth and fifth Vimshottari lords and their boundaries using the same 365.25-day-year convention as Nadi's existing three-level implementation. Compare the first three lords with the existing function in automated tests, and test child-period boundaries. For published events with an explicitly stated local clock, report levels 1–5 at the reported birth time and how levels 3–5 change when the event clock is shifted by ±60 minutes. Stated clocks may be approximate or unverified; no accuracy of a stated clock is presumed. Date-only events do not receive a fictitious noon-based fourth/fifth-level verdict. This follow-up does **not** rank candidates using levels four or five: event clocks are mostly unknown, and a five-second birth-time grid can miss rapid level-five changes. An accurate all-candidate 345 scan would need the full plausible event-time interval and a boundary-aware search.

## Outputs

Store public-only results with source links, case rows, full tied top intervals, event clock assumptions, counts, and hashes of the protocol, inputs and relevant calculation files. Describe the uncertainty of the records, sample size, sampling grid and shared source dependencies. Do not alter production scores or interpret the outcome as proof that a published time is wrong or that a rectified time is correct. Further evaluation after this exploration requires a genuinely unseen, source-audited cohort and a frozen rule.
