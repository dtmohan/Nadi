# Transit reference audit

[Phaladeepika 26.1–2](https://www.siva.sh/phaladeepika/26/1) uses the natal Moon's sign as the principal reference for the chapter's gochara houses. Nadi's `computeGochara` takes this sign explicitly. Overview, Panchanga, the gochara calendar and Panchanga report supply the natal Moon; the Prasna transit table also uses its own Moon-based method. Phaladeepika's [26.41](https://www.siva.sh/phaladeepika/26/41) introduces an Ashtakavarga condition, and Nadi applies an explicitly provisional interpretation of that condition along with its other configured gochara rules.

The Parashari Ashtakavarga timeline is a different calculation. It looks up a planet's own marks and the aggregate marks in the sign that planet occupies. `AvTransitRow.house` is an additional whole-sign label counted from the natal ascendant and does not select the tone. The natal ascendant is itself one contributor to the natal marks, so changing an actual birth ascendant may change the marks. The regression test holds the natal mark tables fixed when varying only the displayed house reference. Overview and the timeline now identify both reference houses and name the Ashtakavarga grade; a Moon-relative number alone is not represented as a gochara verdict.

KP event checks follow transiting lords to natal significators and display natal cusp houses. Parashari v1–v3 use their specific natal and transit targets. Jaimini and BNN use their own natal anchors. General Moon-based gochara is not included in those event scores or their Monte Carlo scores. The separate Panchanga date picker evaluates its selected place at sunrise; that is not necessarily the event instant or location. Adding an event-time Moon-based check would require a scoped rule, the same sky and conditions on real and comparison dates, published-case evaluation and an explicit decision about scoring; it has not been assumed here.
